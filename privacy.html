PAGES privacy & data

Pomegranate × Lily · Updated October 13, 2026

PAGES is an early-stage, account-based Circles app. Its current publicly committed configuration uses Supabase for email sign-in and user data. This notice describes what the application code is designed to handle; deployment and database policy settings still require independent verification.

Information you provide

When you sign in, PAGES sends your email address to Supabase authentication to deliver a one-time sign-in email or code. The app may store a profile with your email address and display name. Using Circles can create records of your circle membership, invitations, messages, missions, milestones, shared commitments, activity history and notifications. Content you choose to share with a Circle is intended to be visible to other authorized Circle participants.

Do not enter health information, banking details, passwords or other highly sensitive information. The system is a prototype, and its production access-control policies have not been independently verified. In particular, the source database policies need a separate review of member email visibility before broad public registration.

Where information goes

GitHub Pages hosts the web application and may process network connection metadata. When PAGES is configured for Supabase mode, sign-in and Circle data are processed by Supabase and its infrastructure. The browser also downloads the Supabase JavaScript client from jsDelivr. These providers may receive connection information such as an IP address. The current client code does not install Google Analytics or advertising tracking pixels.

Browser storage and login

Supabase authentication may keep session tokens in browser-managed storage so you remain signed in. During email sign-in, PAGES also temporarily stores the email address and request time in this app window's session storage for up to 30 minutes, so you can return from Mail without losing the code entry screen; it does not store the six-digit code itself. A local demo mode also exists in source code, but is not a secure multi-user service. All projects under pomegranatexlily.github.io currently share the same browser storage origin. That creates a privacy boundary issue until the projects are on separate hostnames, and is another reason not to use the early build for sensitive personal information.

Who can access data

The application's intended design uses Supabase Row Level Security to control Circle access. Source policies and production configuration must be verified in Supabase before those controls can be treated as operationally confirmed. Other Circle participants may see shared Circle information and display names. Authorization design does not guarantee that every submitted message or record can be removed from another person's device.

Choices, retention and requests

You can sign out to end the current session. Clearing site data may remove local copies of login state but does not delete records already stored by Supabase. A self-service account or full cloud-data deletion workflow is not yet implemented in the reviewed app. Records may persist until manually removed under the provider's data retention and deletion procedures.

For general, non-sensitive questions use the PAGES GitHub issue tracker. It is public and must never be used to post account email addresses, authentication codes, personal messages, private requests, or security vulnerabilities. A verified private contact channel is being established; avoid submitting sensitive requests publicly.
